# IT-Продлёнка

В рамках IT-продлёнки предлагается поработать с музейными каталогами [ГМИИ им. Пушкина](https://www.pushkinmuseum.art/) и создать на их основе приложение для навигации по музею с использованием искусственного интеллекта на базе [Yandex AI Studio](https://aistudio.yandex.ru).

> Мы предоставим всем доступ к Yandex AI Studio и Yandex Cloud на время проведения мероприятия.

## Вайбкодинг

Поскольку мы хотим создать приложения за короткий срок, то ожидаем, что вы все будете использовать вайб-кодинг - программирование с использованием ИИ. Для этого потребуется установить себе на компьютер какой-нибудь кодинг-агент (или несколько).

Мы рекомендуем следующие варианты:

* [SourceCraft CLI](https://sourcecraft.dev/portal/docs/ru/sourcecraft/operations/cli-quickstart) - это утилита для работы с SourceCraft, которая также включает в себя версию OpenCode с некоторым количеством бесплатных лимитов на использование.
* [OpenCode](https://opencode.ai/download) - OpenSource-агент, который доступен в версиях CLI (для командной строки), для десктопа, а также как плагин к VS Code. Включает в себя некоторые бесплатные лимиты на доступ к моделям.

Если у вас есть свои подписки на OpenAI Codex, Claude Code или другие кодинг-агенты - можете использовать их. 

Если лимиты закончатся, вы также можете подключить кодинг-агентов к моделям в Yandex AI Studio по API. **В реальной жизни так делать не рекомендуется из-за существенного расхода токенов**, но если у вас закончатся лимиты в бесплатных моделях - можно воспользоваться этим на сегодняшнем мероприятии. Инструкции по тому, как это сделать для OpenCode и Codex есть [тут](https://github.com/shwars/coding-agents-ai-studio/).

## Помним про основные принципы вайбкодинга

Нам не понадобится создавать большие проекты, требующие дальнейшей поддержки - поэтому слишком сильно заморачиваться не стоит. Но может быть полезным помнить следующие базовые правила:

* **Тестирование результата** кодинг-агентом позволяет вам меньше проверять результаты самостоятельно. Обычно кодинг-агенты сами обучены придумывать методы тестирования результатов, но если у вас есть какие-то тесты, то лучше их явным образом прописать. Например, если описания экспонатов должны быть короче 1000 символов, это можно проверить автоматически скриптом, но об этом стоит попросить кодинг-агента.
* **Максимально информативный контекст модели** - следует строить взаимодействие таким образом, чтобы в контекст модели попадали только релевантные данные, и при этом путь к решению задач был минимальным. Для этого имеет смысл использовать явные указания на то, какие данные надо прочитать, а также навыки (skills). Про полезные для нашей задачи скиллы - ниже.
* **Используйте AGENTS.md**. Этот файл кодинг-агенты всегда по умолчанию читают перед началом работы над проектом. Туда полезно помещать краткое описание проекта, сведения по расположению материалов в папке проекта, технологические требования и т.д.
* **Параллельное ведение документации проекта**. Чтобы при каждом перезапуске кодинг-агента он мог быстро понять предысторию, смысл и состояние проекта, можно просить кодинг-агента всегда вести подробную документацию текущего состояния (архитектуры, структуры базы данных и т.д.) в текстовых файлах, а также историю изменений. Полезный файл для ведения документации есть в [etc/AGENTS-doc.md](etc/AGENTS-doc.md), инструкции или ссылку на этот файл можно добавить в AGENTS.md.

## Где брать открытые данные

В интернет информация по экспонатам Пушкинского музея существует в виде открытых данных. Они описаны [тут](https://www.pushkinmuseum.art/open_data/). Основные наборы:
* Краткий датасет [основных шедевров](https://www.pushkinmuseum.art/json/masterpieces.json), [разделов](https://www.pushkinmuseum.art/json/collects.json) и [зданий](https://www.pushkinmuseum.art/json/buildings.json) музея
* [Полный каталог экспонатов](https://opendata.mkrf.ru/opendata/7705851331-museum-exhibits) из ГосКаталога Музейного фонда

Мы рекомендуем работать с более полным каталогом. Это можно сделать двумя способами:

* Скачав полный каталог всех экспонатов музейного фонда (10+ Gb в архиве) и отфильтровав его по музею (идентификатор ГМИИ им. Пушкина - 110111)
* Скачать только экспонаты ГМИИ по API - для этого вам потребуется [получить API-ключ разработчика](https://opendata.mkrf.ru/item/dev), после чего вы можете использовать подготовленный нами скрипт `scripts/download-data.py` для скачивания данных:
```
python download-data.py --api-key ...
``` 

Для начала можно скачать первые 10000 записей, а затем при необходимости все остальные (более 300 тыс.):
```
python download-data.py --limit 10000 --api-key ...
```

Демонстрации AI Studio также используют сокращённый каталог, извлекая из него нужные данные о локации экспонатов. Для загрузки датасета и преобразования его в упрощенный формат используте скрипт `scripts/prepare-data.py`.

## Skills

В рамках работы над проектами мы рекомендуем использовать следующие скиллы для кодинг-агентов, которые помогают им правильнее выполнять определённые задачи. Для установки этих скиллов скопируйте всё содержимое директории `skills` из репозитория в директорию `.config\opencode\skills`.

### sourcecraft-sites
Создаёт и публикует простой статический сайт на SourceCraft Sites: создаёт публичный репозиторий через CLI `src`, наполняет его файлами `site/index.html` и `.sourcecraft/sites.yaml`, пушит в `main` и сообщает адрес `https://<org-slug>.sourcecraft.site/<repo-slug>`.

Пример запроса: *«Создай сайт на SourceCraft Sites для организации myorg».*

### mobile-web-app
Генерирует файлы мобильного веб-приложения (PWA) из статического сайта: web manifest, service worker, meta-теги для iOS и Android, раскладку мобильного приложения с адаптацией под десктоп. Готовый сайт можно «Добавить на главный экран» на iPhone и Android. Скилл только создаёт файлы; публикацию делает sourcecraft-sites или GitHub Pages.

Пример запроса: *«Сделай сайт мобильным приложением с нижней навигацией — Главная/Каталог/О себе — и опубликуй на SourceCraft Sites».*

### ai-studio
Помогает писать чистые Python-приложения на Yandex AI Studio через OpenAI-совместимый Responses API и другие сервисы Yandex: выбор подходящей модели и контекстных лимитов, настройка клиента, текстовые и мультимодальные ответы, диалоги, стриминг, структурированный вывод через Pydantic, вызовы функций, веб-поиск, RAG и векторные хранилища, Code Interpreter, генерация изображений, Vision OCR и SpeechKit.

Пример запроса: *«Напиши Python-приложение, которое распознаёт текст с фотографии через Vision OCR в Yandex AI Studio»*.
